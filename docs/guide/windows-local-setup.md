# Windows local setup

## Prerequisites and first setup

Choose either the Docker stack or a fully native installation. Commands below use PowerShell on Windows and run from the repository root unless stated otherwise.

| Technology / purpose | With Docker | Without Docker |
| --- | --- | --- |
| Git and PowerShell | Install on the host | Install on the host |
| Docker Desktop / Compose v2 | Install; start the Linux container engine | Not required |
| Node.js 26.13.0 and npm; React 19.3.1, TypeScript, Vite web app | Node/npm run inside the gateway build stage (`npm ci`, `npm run build`); install Node.js 26.13.0 on the host only for web development | Install Node.js 26.13.0 with npm; install web dependencies with `npm ci` |
| Python 3.12 and `uv`; FastAPI / Uvicorn API and dedicated worker | Installed in the backend/worker images | Install Python 3.12 and [uv](https://docs.astral.sh/uv/getting-started/installation/); `uv sync` installs workspace dependencies |
| PostgreSQL 18; SQLAlchemy, psycopg, Alembic | Database container; Python libraries installed in images | Install PostgreSQL 18 locally; Python libraries installed by `uv` |
| FFmpeg / ffprobe; Pillow / pillow-heif media processing | Included in backend and worker images | Install FFmpeg and put **both `ffmpeg` and `ffprobe` on PATH**; image libraries installed by `uv` |
| Caddy 2 gateway / HTTPS | Gateway image serves the built web app and proxies API/media requests | Not needed for local Vite development; install Caddy or another HTTPS reverse proxy for a public deployment |
| Cryptography / Fernet and HTTPX; Meta Instagram API | Python dependencies installed in images; supply configuration below | Python dependencies installed by `uv`; supply the same configuration |
| Kotlin, Jetpack Compose, Gradle / Android SDK | Optional Android client, not part of the Docker stack | Optional; install Android Studio and the project's required SDK/JDK only to build the client, not to use the released APK |
| Firebase Admin / FCM | Optional notification/monitoring integration; requires separate Firebase credentials when enabled | Same; worker dependencies include Firebase Admin |
| Vitest, Testing Library, Playwright; pytest, Ruff, mypy | Development/CI checks, not additional runtime services | Installed through web/Python development dependencies; Playwright browser tests also need browser binaries |

GitHub Actions handles CI and signed Android releases; no local Actions service is required. Docker does **not** remove Node.js/npm from the technology stack: it runs the web build in a container instead of on your host.

### Configure `ops/.env.local`

This is a **server-side** environment file, not `web/.env.local`. Never add secrets to `VITE_*` variables, source control, screenshots, or shared logs. Docker's startup script creates local secrets if the file is absent, preserves existing values, and adds a missing encryption-key assignment. It does not fill in Meta app credentials. Native processes do not load this file automatically: dot-source `Load-Env.ps1` in each API/worker/CLI terminal.

| Variable | Docker local stack | Native local installation |
| --- | --- | --- |
| `POSTGRES_PASSWORD` | Generated on first startup; retain it for the existing database volume | Password set for the local `dojo` login |
| `POSTGRES_USER`, `POSTGRES_DB` | Default to `dojo` | Set both to `dojo` for the native commands below |
| `DATABASE_URL` | Do not add a host URL: Compose constructs `postgresql+psycopg://…@db:5432/dojo` | Add `postgresql+psycopg://dojo:YOUR_URL_ENCODED_PASSWORD@localhost:5432/dojo`; adjust port if necessary |
| `PUBLIC_BASE_URL`, `PUBLIC_HTTPS_ORIGIN` | Both `http://localhost:9081` | Both `http://localhost:3000` |
| `COOKIE_SECURE` | `false` for loopback HTTP | `false` for loopback HTTP |
| `SIGNED_URL_SECRET` | Generated on first startup | Generated by the native command below; keep a stable random secret |
| `MEDIA_ROOT` | Compose fixes this to `/media` in the shared volume | Set an absolute writable path, e.g. `C:/aisomedo-data/media`, shared by API and worker |
| `WORKER_HEALTH_PATH` | Keep the container default `/run/dojo-worker/health.json` | Replace the example's Linux path with a writable Windows path, e.g. `C:/aisomedo-data/worker-health.json` |
| `WORKER_INTERVAL_SECONDS` | Default `10` | Keep `10` unless intentionally tuning it |

Create the native media/health parent directories before starting. If native `DATABASE_URL` is omitted, `Load-Env.ps1` derives **localhost:5434**, intended for the development database container, not the native PostgreSQL default. Existing process-level `DATABASE_URL` and `COOKIE_SECURE` can override the file; use a fresh terminal when changing installations. Do not point native and Docker workers at the same installation simultaneously.

For public publishing, replace both public URL values with the **same publicly reachable HTTPS origin**, enable `COOKIE_SECURE=true`, and configure the HTTPS gateway/reverse proxy. Instagram must be able to fetch signed media URLs from that origin; `localhost` is not sufficient. Do not expose PostgreSQL publicly.

#### Meta values and the currently supported connection flow

**Current limitation:** `backend/src/backend/deps.py` wires OAuth to `StubMetaOAuthProvider`. Supplying app credentials alone does **not** enable real browser OAuth. The real connection path currently implemented is **Instagram Login access-token entry**, validated through `graph.instagram.com`. Use **Instagram erişim tokenı → Token ile bağlan** in setup. A Facebook/Page token is not interchangeable with an Instagram Login token.

| Variable | What to supply / current behavior |
| --- | --- |
| `META_TOKEN_ENCRYPTION_KEY` | **Required even for local startup.** A Fernet key: URL-safe base64 encoding of 32 random bytes, generated by Docker startup or the native command below. API and worker must share it. Back it up securely: replacing it makes stored tokens unreadable. This is not an app secret or access token. |
| `META_GRAPH_VERSION` | `v26.0`, the repository default for real Graph API calls. Change only after checking compatibility. |
| `META_APP_ID` | App ID from the relevant Meta app dashboard for the OAuth integration. The current stub does not perform real authorization with it; it is not required to paste an independently obtained Instagram Login token. |
| `META_APP_SECRET` | Matching server-side app secret from Meta's dashboard. Do not use an Instagram password. Current stub does not exchange real authorization codes; manual token entry does not require this value. |
| `META_REDIRECT_URI` | Intended backend callback, e.g. `https://your-domain.example/api/meta/oauth/callback`. Defaults to the public origin plus that path. For a real OAuth integration, register the exact URI in Meta's valid OAuth redirect settings; setting it here does not replace the stub. |
| `META_ALLOWED_RETURN_URIS` | Comma-separated exact allowlist of client destinations **after** the backend callback, not Meta's callback registration. Leave empty if no return URI is requested; add only destinations your clients actually handle, never arbitrary external URLs. |
| `META_OAUTH_SCOPE` | The example lists Facebook Login scopes: `instagram_basic,instagram_content_publish,pages_show_list,pages_read_engagement`. **Current provider does not read this variable.** Changing it cannot enable OAuth or grant permissions to a manually supplied token. |

To obtain a usable token:

1. Use an Instagram **professional Business or Creator** account. In [Meta for Developers](https://developers.facebook.com/), create/select your app and configure **Instagram API with Instagram Login**. Add/authorize the test account and accept any required tester invitation for development access.
2. Obtain an Instagram User access token with **`instagram_business_basic`** and **`instagram_business_content_publish`**, using Meta's supported setup/login flow. Prefer a long-lived token; token generation/exchange happens outside Aisomedo's stub OAuth flow. These are different permissions from the Facebook Login scope list above.
3. Paste the token into the application's **Instagram erişim tokenı** field and choose **Token ile bağlan**. Do not add an invented `META_ACCESS_TOKEN` setting: this flow stores the token encrypted in the database. A successful account lookup does not prove publishing permission; missing publishing permission can surface when publishing.
4. Development access is limited to eligible app-role/test accounts. Before serving other accounts, obtain the required Meta access level/App Review and any required business verification. Check [Meta's current Instagram Login documentation](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/) for account, permission, and token-lifetime requirements.

Firebase notification/monitoring credentials are separate from Meta. Only enable those integrations after supplying the corresponding Firebase service-account file and project ID; neither is needed for a basic local web installation.

After editing Docker configuration, rerun `start-local.ps1` to recreate affected services; restart the worker explicitly with `-StartWorker` if it is in use. For native runs, stop the processes, open fresh terminals, reload the file, and restart them. Do not regenerate secrets on each restart.

## Option A — Docker stack

Run this block in PowerShell from the folder where you keep projects. Use a new destination; if you already cloned the repository, skip the first two lines and run the last command from its root.

```powershell
git clone https://github.com/35HaRRy/aisomedo.git
Set-Location aisomedo
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\start-local.ps1 -PairingCode
```

Open **http://localhost:9081**. Click **Uygulamayı aç**, enter the code printed in your terminal and a browser name, then click **Eşleştir**. Codes expire and work once; run the command again for another code. Do not share them publicly.

The script uses its own `aisomedo-local` Docker project, named data volumes, and `ops/.env.local`. It preserves an existing environment file and does not read `ops/.env`. The web port is bound to this computer only.

The worker is off by default. To enable local rendering and scheduling, run the following and type `START` when asked. An already configured worker can publish after a valid approval, so use a test installation and keep its plan disabled while exploring.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\start-local.ps1 -StartWorker
```

In the browser setup wizard, connect Instagram, choose a publication plan, read and accept the media policy, upload a logo, and save a caption template. Opening/closing cards are optional. A valid disabled plan can be saved without turning scheduled publishing on.

**Local startup is not a complete Instagram publishing setup.** Real publishing needs a supported Instagram professional account, Meta permissions and credentials, and a publicly reachable HTTPS server for media delivery. Never use private class media without the required permissions.

See [first setup and installation](getting-started.md) for browser steps, external requirements, restart/stop commands, and Android connection.

## Option B — without Docker

1. Install the native prerequisites above. Confirm `git`, `node`, `npm`, `uv`, `psql`, `ffmpeg`, and `ffprobe` are available in a new PowerShell terminal. Start the local PostgreSQL service. Clone the repository and enter its root as shown in Option A, but **do not run `start-local.ps1`**.
2. Create a separate local database and login. These commands assume PostgreSQL listens on `localhost:5432`; enter the administrator password when prompted. Skip creation if this dedicated database/login already exists. Set a strong password at the `\password` prompt and use the same value as `POSTGRES_PASSWORD` below.

```powershell
psql -h localhost -p 5432 -U postgres -c "CREATE ROLE dojo LOGIN;"
psql -h localhost -p 5432 -U postgres -c "\password dojo"
psql -h localhost -p 5432 -U postgres -c "CREATE DATABASE dojo OWNER dojo;"
uv sync --all-packages
```

3. If `ops/.env.local` does not exist, copy `ops/.env.example` to it. **Do not overwrite an existing environment file or reuse Docker database credentials against a different database.** Edit the native values in the configuration section above. Generate the missing secrets once, then paste the printed assignments into the file:

```powershell
if (-not (Test-Path .\ops\.env.local)) { Copy-Item .\ops\.env.example .\ops\.env.local }
uv run --project backend python -c "import secrets; print('SIGNED_URL_SECRET=' + secrets.token_hex(32))"
uv run --project backend python -c "from cryptography.fernet import Fernet; print('META_TOKEN_ENCRYPTION_KEY=' + Fernet.generate_key().decode())"
```

4. Load configuration and initialize the schema before starting any application process:

```powershell
. .\ops\Load-Env.ps1 -EnvFile .\ops\.env.local
uv run --project backend python -m dojo.schema
$env:SKIP_CREATE_ALL = '1'
uv run --project backend dojo-create-pairing-code create-code
uv run --project backend python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload
```

5. Leave the API running. In a second terminal, from the repository root, start the web app:

```powershell
Set-Location web
npm ci
npm run dev
```

Open **http://localhost:3000**, then pair with the printed code. Vite proxies `/api` and `/pub` to the API on port 8000. If the code expires, load the same environment in another root terminal and rerun the pairing-code command.

6. Rendering and scheduling need exactly **one** worker. Only when ready, in a third root terminal:

```powershell
. .\ops\Load-Env.ps1 -EnvFile .\ops\.env.local
$env:SKIP_CREATE_ALL = '1'
uv run --project worker python -m worker.main
```

Keep the plan disabled while exploring: a worker with stored credentials and valid approval can publish. Stop native processes with **Ctrl+C**. API and worker must use the same database, media directory, signing secret, and encryption key. The native commands deliberately load `.env.local` explicitly; `run-backend.ps1` defaults to `ops/.env` instead.
