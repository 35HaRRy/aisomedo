# Issue #24 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Committed OpenAPI contract with generated TS/Kotlin clients, CI drift checks, and Android N/N-1 version enforcement with update prompt.

**Architecture:** FastAPI exports `backend/openapi.json`; a stdlib-only Python generator emits TS and Kotlin clients; a public `/api/compat` endpoint plus middleware enforces the version floor for Bearer device clients.

**Tech Stack:** FastAPI, Python stdlib generator, TypeScript fetch, Kotlin stdlib + HttpURLConnection.

**Spec:** `docs/superpowers/specs/2026-09-30-issue-24-design.md`

## Global Constraints

- Python 3.12, `ruff` line-length 100, `mypy` strict for `backend` package.
- No new runtime dependencies (stdlib only in generator and versioning).
- Browser session-cookie traffic is never version-blocked.

## Review Focus

- Bearer request without version header must still get 426, not a silent pass.
- `/api/compat`, `/health`, `/ready` must stay reachable for outdated clients.
- Non-HTTPS `ANDROID_UPDATE_URL` must fail closed.
- Generator output must be byte-deterministic for CI diff.
- Web banner must not block dashboard when versions match.
